# Changelog

All notable changes to `@mmdx/studio` (named `mmdx` before 0.3.0). The project follows [semantic versioning](https://semver.org/); below 1.0, a minor version may change public API, listed under **Changed (breaking)**.

## Unreleased

### Added

- **An image library**: `<mmdx-editor>`'s new `images` property takes the host's image store, an `ImageStore` (`list`, `get`, `put`, optional `delete` and `subscribe`; `@mmdx/studio/adapters`, with `memoryImageStore` and `httpImageStore`). The image tool has three tabs — **Library** (the store's pictures as thumbnails, searched by name and paged; a picture the image policy refuses is dimmed), **Upload** (put into the store, else the `uploadImage` hook) and **URL** — and the toolbar's first item for an image node, **Change image**, is a menu of four — **From the library…**, **Upload…**, **By URL…** (each where the host provides it) and **Icon…** — as are the Properties panel's buttons. An image references the stored picture's `url`, a URL or a store reference the host's `resolveUrl` maps to one.
- **Sequence participant types**: Mermaid's eight participant types are drawn as Mermaid draws them — participant, actor, boundary, control, entity, database, collections and queue — and the participant shape picker writes them to the code (`actor` / `participant` as the keyword, the others as `@{ "type": … }`, keeping the rest of `@{}`, the alias and `create`); Rounded and Stadium stay mmdx-only looks in metadata. A type Mermaid does not draw is a `seq.bad-type` warning.
- **Icons and images on participants**: a participant's icon is a label token in its display name (the Icons tool adds an alias when there is none, `participant A as fa:fa-user A`), drawn above the name by default; its image is metadata `img`, and Mermaid's `properties A: {"icon": "https://…"}` is drawn as the image and kept. The Image tool works in sequence diagrams; icon tokens in messages and notes are drawn.
- **Every Mermaid flowchart shape**: all 53 shapes of Mermaid 11.17's `A@{ shape: … }` and their aliases, 11.15–11.17's `datastore`, `folder`, `bucket`, `console`, `browser` and `person` included, drawn by mmdx from one shape catalogue — plus the sequence participant figures, the mindmap's default node, the state diagram's choice and note, and icon and image frames for the diagram types that use them later. A [Shapes](https://udamir.github.io/mmdx/guide/shapes) guide page lists them with previews.
- **Lossless node data**: `A@{ … }` is read like Mermaid reads it (double quotes protect `}` and `,`, blocks over several lines), every key is kept — `icon`, `img`, `w`, `h` and unknown ones — and edits rewrite only the values they change.
- **Shape name warnings**: an unknown shape name (`flow.unknown-shape`) and a name Mermaid rejects such as `lean_r` (`flow.shape-name`, with a fix that writes the short name).
- **`flow.meta-shape`**: the editor's code panel lists flowchart shapes kept only in metadata (files of 0.1–0.3), with a fix that writes them to the code.
- A Storybook story with every shape next to stock Mermaid's drawing of it.
- **Image policy**: `configure({ imagePolicy })`, the components' `ctx` and `createContext({ imagePolicy })` decide which image URLs a diagram may show — `https:` from any host by default; `http:`, embedded `data:` images (base64 PNG, JPEG, GIF, WebP, SVG or AVIF up to a size) and relative URLs only when the host enables them; `hosts` limits images to a list and `protocols: []` turns them off. A refused image is never written to the SVG: it is drawn as a placeholder and reported as an `image.blocked` warning with the reason. `checkImageUrl`, `safeImageUrl`, `DEFAULT_IMAGE_POLICY` and the `ImagePolicy` type are exported from `@mmdx/studio/core` ([Security → Image policy](https://udamir.github.io/mmdx/guide/security#image-policy)).
- **Images, inline icons and bold and italic text in the drawing**: the groundwork for image and icon nodes and Mermaid's markdown labels — images fitted into a box (contain, cover or stretch), icons inside a line of text, bold and italic words that wrap like plain text, and changed words that keep their styling in the diff. The diagram types start using them with the image and icon nodes.
- **Icon packs**: `configure({ iconPacks })` registers [Iconify JSON](https://iconify.design/docs/types/iconify-json.html) packs the way Mermaid's `registerIconPacks` takes them — `{ name, icons }` or `{ name, loader }`, the loader called once, on the first icon of the pack a diagram shows, and tried again 30 s after a failure — and the viewer, editor and diff take packs of their own (`iconPacks`). Diagrams name icons as `pack:name`: label tokens in every diagram type (`fa:fa-car Car`, `azure:computer-vision Vision`; a prefix is an icon only when its pack is registered, Font Awesome's always), icon nodes (`@{ icon: "logos:aws-ec2" }`) and mindmap `::icon(fa fa-book)`. Rendering stays synchronous: an icon still loading is an empty box of its size and the components render again when it arrives; an unknown one is a "?" placeholder with an `icon.unknown` warning. Monochrome icons take the item's colour, logos keep theirs. The diagram types draw them as they gain icon support (flowchart icon nodes and labels first).
- **A built-in icon set**: about 250 generic icons from Tabler Icons (MIT) under Tabler's own prefix, `tabler:` (people, devices, documents, data, network, security, status, time, money, communication, arrows, shapes, brands), in a chunk of its own loaded on first use (about 20 kB gzip); a host's full `tabler` pack replaces it, `configure({ builtinIcons: false })` turns it off. The licence is in `THIRD-PARTY-NOTICES`.
- **Font Awesome look-alikes**: `fa:fa-car`, `fab:fa-github` and about 350 other common Font Awesome names draw a built-in look-alike when no Font Awesome pack is registered, with an `icon.fa-fallback` note.
- **Stock Mermaid gets the same icons**: the fallback renderer and the editor's Plain Mermaid preview pass the packs, the built-in set included, to `mermaid.registerIconPacks` before rendering.
- **Icons on the server**: `renderToSvg` loads the icons a source references before it renders and takes `iconPacks`; `@mmdx/studio/core` exports `createIconRegistry` and `iconNamesOf`; the markdown plugins take `iconPacks` (the rehype plugin waits for icons a page needs) and `preloadIcons()` serves markdown-it. The render worker receives the icons it draws from the main thread.
- **`mmdx-icons`**: a command that builds an icon pack with Mermaid Chart's names (`azure:computer-vision`) from the official Azure, AWS and Google Cloud icon downloads (`npx mmdx-icons build --from <dir> --prefix azure --naming azure --out azure.json`), with naming tables per provider and an override list.
- An [Icons](https://udamir.github.io/mmdx/guide/icons) guide page, and a Storybook story of the Mermaid fallback drawing registered icons.
- **PNG export includes remote images**: each image is fetched (CORS, no credentials) and put into the PNG; one whose host does not allow it is a placeholder, with a toast and an `export.image-missing` warning.
- **Image in the editor's tool dock** (`G`), beside Shapes, shown when the diagram type takes images: dragged onto the canvas (or clicked, for the middle) like a shape, it adds an image item with the placeholder — an empty URL (`img: ""`), drawn as a dashed frame with a mountain glyph without a warning — whose picture is then chosen from the toolbar or Properties. Text, icons, containers and connectors have no dock tools: they are made where you work — the Shapes menu's text block, the floating toolbar's and Properties' Icon, ⌘G, a node's connection handles.
- **`configure({ resolveUrl })`**: the host resolves the URLs diagrams point at — images and links — before the image and link policies check them: called with each URL as written and its kind (`'image'`, `'link'`), it returns the URL to use (a relative path made absolute, an attachment's name made its download URL) or null to keep it. The code keeps what was written; also a `CoreContext` option (`ctx`, `createContext`), and `checkImageUrl` / `safeImageUrl` take it as a third argument. While it is set, diagrams render on the main thread. `relativeUrlResolver(base)` in `@mmdx/studio/adapters` resolves relative URLs against a base (the document's folder).
- **The Shapes menu as Mermaid Chart lays it out**: the flowchart's shapes in Basic, Process and Technical, each once, six to a row, every section open without a scrollbar, no search field and no recently used row (the shapes Mermaid Chart lacks end the Technical section; the text block is a "T"); click or drag to add, Alt-click to give the selected nodes a shape. The floating toolbar's shape picker shows the same list, with the stacked style below it.
- **Icon picker** ("Choose an icon…"): search across the registered icon packs, a chip per pack (an unloaded pack loads when chosen), recent icons, a virtualised grid and the licence on hover. It sets the selected items' icon — an icon node's `icon` key, a `pack:name` token at the start of any other node's label — or removes it.
- **Image tool**: an image by URL, checked live against the image policy, adds a flowchart image node (`n5@{ img: "https://…", h: 200, w: 200, pos: "b" }`) or sets a selected node's image. Pictures are never embedded: dropped, pasted or chosen files go to the host's new `uploadImage` hook (an editor option and property), with an offer to reduce pictures over 1600 px; without it they are refused with a toast.
- **Emoji picker**: `⌘;` / `Ctrl+;` while editing a label on the canvas, and a ☺ button in the Properties label fields — groups, recents, search by CLDR name and keyword, skin tones — inserting the emoji at the caret as plain text. The data (English, from emojibase, MIT) is a lazy chunk under 30 kB gzip, built by `tools/build-emoji.mjs`.
- **Icon and image controls**: the floating toolbar's Icon button (a dot marks an item with one), an Icon & image popover and an H field for icon and image nodes, and Icon and Image sections in Properties (frame, label position, width, height, aspect lock, fit), written to the node's data in the Mermaid code.
- **Flowchart icon and image nodes are drawn**: `@{ icon, form, label, pos, h, w }` as the icon in its frame (none, square, circle, rounded — painted with the node's fill and stroke, the icon in the code's stroke colour) with its caption above or below, sized as Mermaid sizes it; `@{ img, label, pos, w, h, constraint }` as the picture, at its own size when `w` and `h` are not given (the viewer and the editor lay the diagram out again once the browser knows it; 96 × 96 with an `image.size-unknown` note where it cannot), with the aspect lock and the layout metadata's `imgFit`. The selection box holds the asset and the caption; connectors end on the asset. See [Flowchart content](https://udamir.github.io/mmdx/guide/flowchart).
- **Icons in flowchart labels**: `fa:fa-car Car`, `fab:fa-github` and tokens of any registered pack are drawn as icons in node and edge labels and subgraph titles.
- **Markdown labels**: flowchart labels written as markdown strings (`` "`**bold** *italic*`" ``) are drawn with their emphasis and line breaks and wrap by themselves at 200 px (`markdownAutoWrap: false` and `flowchart.wrappingWidth` in the frontmatter change that). In the editor, Bold and Italic above the label being edited (`⌘B`, `⌘I`) wrap the selected words in `**` / `*`, and **Make rich text** turns a plain label into a markdown string.
- **More of Mermaid's flowchart syntax**: invisible links (`~~~`, layout only); edge ids (`A e1@--> B`, which become the edge's metadata id) and edge data — `animate` and `animation` (dashes flowing along the line, still in exports, stopped by reduced motion and by the new **Animate edges** view setting) and `curve`; `linkStyle … color` (the label's colour) and `interpolate`; the frontmatter's `flowchart.curve`; `classDef default`; several classes (`class a,b c1,c2`, `A:::c1:::c2`); classes on subgraphs; `click … "tooltip"` as a hover tooltip; the `title` drawn above the diagram; `accTitle` and `accDescr` (also the `accDescr { … }` block) as the SVG's `<title>` and `<desc>` and the viewer's accessible name and description; a repeated `subgraph X` adds to the first, as in Mermaid 12.1.
- **Files from Mermaid Chart** open as they are (node data in separate statements, `@{ shape: text}`, `style` on icon nodes, `layout: fixed` kept and ignored) and stay unchanged until edited.
- **Editing icon and image nodes**: the resize handle sizes the icon or picture and writes `h` / `w` into its node data; **Convert to icon node** (toolbar popover and Properties) makes a label's leading icon the node's.
- Two examples: Architecture with icons and Icons, images and rich labels.
- **Subgraph `direction`**: `direction LR` inside a flowchart subgraph lays out its contents that way, as Mermaid honours it (not when a link from outside reaches a node inside); it was read and ignored.
- **Reset positions in this group**: a subgraph's ⋮ menu, its right-click menu and Properties forget the hand-placed positions inside that subgraph only, and auto layout arranges its contents again while the subgraph keeps its place.
- **`canvas.layout: "legacy"`** (`%%@ canvas {"layout":"legacy"}`) keeps the earlier automatic layout of flowcharts with subgraphs, for one minor release.
- **Mindmaps**, a fourth diagram type drawn by mmdx: the viewer, the editor, `<mmdx-diff>`, History, `renderToSvg`, SSR and the markdown plugins draw Mermaid mindmaps instead of handing them to stock Mermaid (the viewer and the diff load their code the first time a page shows one). A [Mindmaps](https://udamir.github.io/mmdx/guide/mindmap) guide page describes them.
- **Mindmap syntax as Mermaid reads it** (11.17 and 12.2): indentation counted in characters (a tab is one), one root, `id[text]` and bare lines, quoted and markdown text over several lines, the seven shapes (default, `[ ]`, `( )`, `(( ))`, `)) ((`, `) (`, <code v-pre>{{ }}</code>, with the lexer's `id(text(` cloud and `(-text-)` default), `::icon(…)` and `:::classes` on the next line, comments; frontmatter `config.mindmap.colorBy` (`branch` / `depth`) and `maxNodeWidth` are read. Problems are reported as `mm.header`, `mm.syntax`, `mm.second-root`, `mm.dangling` (errors, as Mermaid fails on them), `mm.classdef` (a `classDef` or `style` line, which Mermaid draws as a node) and `mm.icon-not-drawn` (stock Mermaid does not draw `::icon()`; mmdx does).
- **A tidy-tree mindmap layout**: deterministic, never overlapping, the first-level branches split between the root's two sides by the height of their subtrees (clockwise in code order), or all to the right, or top down (`canvas.mindLayout`: `both`, `right`, `down`, and page presets of the same names); each subtree's layout is cached, so an edit lays out its own branch and its ancestors. It differs from stock Mermaid's force layout on purpose: a map keeps its shape while it is edited.
- **Mindmap drawing**: the root in the theme's look, default nodes as a label over an underline in the branch colour, shaped nodes filled with it, branches as curves tapering 11 / 8 / 5 / 3 px; colours by first-level branch (Mermaid's sections) or by depth; every label read as markdown (bold, italic, icon tokens) and wrapped at `maxNodeWidth`; `::icon()` drawn above the label; `:::class` drawn with the preset of that name; a folded branch with a +N badge.
- **Mindmap metadata**: `%%@ node <id>` lines with `side` (a first-level branch's side of the root), `dx` / `dy` (a nudge of a node and its subtree), `collapsed` (a folded branch), `section` (one of the theme's twelve branch colours), `img` (a picture above the label, through the image policy) and the usual style keys. A node without an id of its own (a bare line, brackets only, a repeated id) is `mm<k>` by its place in the code, and the editor carries its metadata along when lines move.
- **A `mindmap` theme section** in the eight built-in themes — `root`, `node`, `nodeShapes`, `nodePresets` (`idea`, `urgent`, `done`, `question`, `muted`, `plain`), `branch`, `sections` (`"0"`…`"11"`, palette references, so every theme recolours them) and `pagePresets` (`both`, `right`, `down`) — validated like the others and in the theme JSON schema. The theme editor has a Mindmap gallery (Root, Node, Branch, Sections, Page) and a Mindmap preview tab.
- **Mindmap editing**: outline keys — `Tab` adds a child, `Enter` a sibling, `⇧Tab` / `⌥←` and `⌥→` move a node out and in, `⌥↑` / `⌥↓` (and `⌘[` / `⌘]`) trade it with a sibling, the arrows walk the tree, `F2` edits, `Space` folds, `⇧Del` deletes a node and keeps its children; a `+` handle and a fold chevron on the selected node, the +N badge unfolds; dragging re-parents, reorders (with an insertion line) or moves a first-level branch to the other side of the root, Alt-drag copies; `⌘C` / `⌘V` / `⌘D` on branches (written ids made unique); pasting indented text, a Markdown list or a Mermaid mindmap onto a node makes a subtree. The Shapes menu and the shape picker write Mermaid's seven shapes in the code; icons are written as label tokens (`fa:fa-book Book`, which stock Mermaid draws), replacing an `::icon()` line; images go to metadata `img`. Page properties set Colours (by branch, or by depth in the frontmatter) and the layout. A new mindmap starts from `root((Topic))`, from the Mindmap card of the "Start a diagram" chooser or the studio's New menu.
- **Mindmaps in the diff and History**: nodes matched by written id, place in the tree, label and parent, then label; a new parent or sibling order is a layout change, label, shape, icon and picture are content, classes and looks are style; the merged picture keeps removed nodes in their old place and marks renamed labels word by word.
- The viewer's accessible name of a mindmap is "Mindmap: N nodes" (`label.mindmap`), and `outline()` gives its tree. New strings: `label.mindmap`, `type.mindmap`, `group.noMindmap`, `tools.mindShapes`, `tb.orderMind`, `page.mindLayout`, `page.colorBy`, `page.colorByBranch`, `page.colorByDepth`, `te.mindmap`, `te.item.root`, `te.item.branch`, `te.item.section`.
- Two examples: Mindmap: Product launch and Mindmap: Study notes, with their version histories.
- **State diagrams**, a fifth diagram type drawn by mmdx: the viewer, the editor, `<mmdx-diff>`, History, `renderToSvg`, SSR and the markdown plugins draw Mermaid's `stateDiagram` and `stateDiagram-v2` instead of handing them to stock Mermaid (the viewer and the diff load their code, with the shapes only state diagrams use, the first time a page shows one). A [State diagrams](https://udamir.github.io/mmdx/guide/state) guide page describes them.
- **State diagram syntax as Mermaid reads it** (one grammar in 11.17 and 12.2, reproduced from Mermaid's lexer rule by rule): states, `state "Text" as id` and `id : text` (the first text is the title, the others description rows), transitions with labels, `[*]` as one start and one end per scope, composites nested to any depth with `--` concurrency regions, `<<choice>>` / `<<fork>>` / `<<join>>` (and `[[…]]`), one-line and multi-line notes, `direction` at the top and in composites, `classDef`, `class`, `:::` on transition ends, `style`, `click`, `accTitle` / `accDescr`, the frontmatter `title`, `%%` and `#` comments; `hide empty description`, `scale … width` and floating notes are accepted and ignored. Mermaid's rules are kept: `;` ends a label, `%%` after a label is part of it, `direction TD` is two states, a state's kind comes from its first mention and its composite from the last one that mentions it. Problems are reported as `state.header`, `state.syntax`, `state.single-word`, `state.unclosed`, `state.composite-description` (errors, as Mermaid fails on them; the line is skipped and the rest still draws), `state.semicolon` and `state.td` (warnings with fixes), `state.kind-late`, `state.classdef-default` (applied by mmdx, rejected by stock Mermaid; fix: remove the line), `state.cross-composite` (a transition between two composites' states, drawn) and `state.bad-style`. The model is checked against the one Mermaid's own StateDB builds.
- **State diagram layout** on the compound layout: each composite and each concurrency region laid out as a container of its own in its own direction (top to bottom without one, the parent's when a transition from outside reaches inside, as Mermaid does), notes beside their state, transitions routed around composites that hold neither end; hand-placed states, fixed composite frames, bend points and routing as in flowcharts.
- **State diagram drawing**: states as rounded boxes with their title and, under a divider, their description rows; the start a filled dot, the end a dot in a ring, a choice a diamond, fork and join bars across the flow; composites as frames with a title band and dashed lines between regions; notes as folded-corner boxes joined by a dashed line; transitions as arrows with their labels on a halo; markdown, icon tokens (in titles, rows, transition labels and notes) and `<br/>`; `click` links through the link policy with their tooltips; the frontmatter title above the diagram.
- **State diagram metadata**: `%%@ node`, `group`, `edge` and `note` lines for states, composites, transitions (`from->to`, `#2`…) and notes (`n1`, `n2`… in code order, carried along by the editor), with the flowchart's keys, `img` (a picture above a state's title, through the image policy) and `shape` (a catalogue shape, mmdx only). Pseudo-states are `[*]start` / `[*]end`, `X/[*]start` inside composite X and `X/2/[*]start` in its second region; ids with `[` or `]` are URI-encoded in metadata lines (`%5B*%5Dstart`). `canvas.composites` (`single`, `palette`) draws every composite in one style or each in a colour of its own.
- **A `state` theme section** in the eight built-in themes — `node`, `nodeShapes`, `nodePresets` (`active`, `done`, `waiting`, `error`, `idle`, `highlight`), `start`, `end`, `choice`, `fork`, `composite`, `compositePresets` (`plain`, `tinted`, `lane`), `compositeColors` (`"0"`…`"7"`, palette references), `note`, `notePresets` (`info`, `warning`), `transition`, `transitionPresets` (`success`, `error`, `async`, `strong`) and `pagePresets` (`whiteboard`, `grid`, `technical`, `colored`: Coloured composites) — validated like the others and in the theme JSON schema. The theme editor has a State diagram gallery (State, Start, End, Choice, Fork / join, Composite state, Composite colours, Note, Transition, Page) and a State preview tab.
- **State diagram editing**: the Shapes menu (`S`) has State, Start, End, Choice, Fork, Join, Composite state and Note — dropped into the composite and region under the point; a start, an end and a note next to a state (`[*] --> s`, `s --> [*]`, `note right of s : Note`), refused with a toast where Mermaid has no place for them (a second start in a scope, an end with no state before it). Connecting writes the transition in the scope both ends share, else at the top level, and refuses transitions into a start, out of an end or across a composite's start or end; reconnecting rewrites an end in place or moves the line. Titles keep the form in use (`state "Text" as id`, `id : text`); Properties set a state's kind (state, choice, fork, join) and description rows, a composite's direction and regions (Add region writes `--`), a note's side; ⌘G makes a composite, Ungroup unwraps one (asking before its inner starts and ends are rewired), Delete asks whether a composite's contents go with it; copy, paste, duplicate and Alt-drag copy states and composites with new ids and the transitions between the copies. Icons are written as label tokens at the start of a title, images to metadata `img`, other shapes to metadata `shape`. A new state diagram starts from `stateDiagram-v2`, from the State diagram card of the "Start a diagram" chooser or the studio's New menu.
- **State diagrams in the diff and History**: states, composites and transitions matched as in flowcharts (a removed and an added state with the same title and kind are a rename), notes by their state and side, pseudo-states by id; a move into another composite or region, a composite's direction or regions and a note's side are layout changes, titles, description rows, kinds, labels, note text and links content, classes, styles and looks style; the merged picture keeps removed items in their old composite and marks changed text word by word.
- The viewer's accessible name of a state diagram is "State diagram: N states, M transitions" (`label.state`), and `outline()` lists its states with their transitions, composites with their contents, and notes. New strings: `label.state`, `type.state`, `tools.stateShapes`, `state.kind`, `state.kind.state`, `state.kind.choice`, `state.kind.fork`, `state.kind.join`, `state.rows`, `state.rowsHint`, `state.direction`, `state.dirDefault`, `state.addRegion`, `state.addRegionTip`, `state.noteSide`, `state.left`, `state.right`, `state.deleteTitle`, `state.deleteMsg`, `state.cancel`, `state.keepContents`, `state.deleteContents`, `state.deletedKept`, `state.deletedAll`, `te.state`, `te.section.state`, `te.item.state.node`, `te.item.start`, `te.item.end`, `te.item.choice`, `te.item.fork`, `te.item.composite`, `te.item.compositeColor`, `te.item.transition`.
- Two examples: State diagram: Order lifecycle (composites, a choice, fork and join, concurrency regions, notes) and State diagram: Traffic light, with their version histories.
- **Icons and images placed by metadata** in mindmaps and state diagrams, whose code has no icon or image node: `iconPos` draws a label's leading icon token inline before the text (`l`, the default; a mindmap `::icon()` defaults to `t`), above it (`t`) or below it (`b`), `iconSize` sizes it and `iconColor` colours it (a colour or palette reference); `imgW` / `imgH` size the metadata picture (one of them alone keeps its aspect; neither: its own size up to 160 px, else 96 × 72) and `imgFit` (`contain`, `cover`, `stretch`) fits it. States and mindmap nodes size and space them alike, and an image not chosen yet (`img: ""`) draws the placeholder in a state as in a mindmap. The keys are validated and in the metadata JSON schema (also for participants and entities, ahead of their icons). Properties of a mindmap node or a state has **Position** and **Icon size** for its icon and **Width**, **Height** and **Fit** for its picture, written to the metadata. New strings: `props.iconPos`, `props.iconSize`, `media.iconPos.l`, `media.iconPos.t`, `media.iconPos.b`.
- **The portable export says what it leaves out**: pictures and catalogue shapes kept in metadata (`img`, `shape`) have no Mermaid syntax, so a toast after **Export → Portable Mermaid (.mmd)** and a line in the Plain Mermaid dialog say so ("1 image and 2 shapes are mmdx-only and are not in the portable file"); label icon tokens and `::icon()` are code and stay. New strings: `export.only.image1`, `export.only.imageN`, `export.only.shape1`, `export.only.shapeN`, `export.only.and`, `export.only1`, `export.onlyN`.
- **Sequence syntax as Mermaid's lexer reads it** (11.17 and 12.2, the model checked against Mermaid's SequenceDB): all 26 arrow tokens in the lexer's order — the 16 half arrows of 11.17 (`-|\`, `-|/`, `-\\`, `-//`, their dotted `--` forms and the reversed `/|-`, `\|-`, `//-`, `\\-` forms), drawn as a half head or a stroke above or below the line at the receiver or, reversed, at the sender; central connections `A->>()B`, `A()->>B`, `A()->>()B`, ending at a small circle on the lifeline; every `autonumber` statement (`off`, a start, a start and a step, several in one diagram), numbered as Mermaid numbers them (every message counts, messages to the sender included), in the drawing and the outline; `create participant` / `create actor` with the participant's head at its creating message's row and its lifeline starting there, `destroy X` with the lifeline ending in a cross at the destroying message; `accTitle` and `accDescr` (one line or a block) as the SVG's `<title>` / `<desc>` and the viewer's accessible name; `@{ "alias": … }` (11.13+; an `as` alias wins, as in Mermaid) and `type` in unquoted YAML; `properties` and `details` read and kept. Mermaid 12.1's forms (whitespace before `@{`, a hyphen in an id with `@{…}`, `Link` / `Links` / `Properties` / `Details` as ids) are read and reported as the info `seq.v12-syntax`; mmdx never writes them. New warnings: `seq.create-existing`, `seq.create-message`, `seq.destroy-message` (what Mermaid rejects) and `seq.bad-json` (a `links` or `properties` value that is not a JSON object). A [Sequence diagrams](https://udamir.github.io/mmdx/guide/sequence) guide page describes them.
- **Participant link menus**: `link A: Label @ url` and `links A: {"Label": "url"}` give a participant its links, through the link policy; the first one is its link, and with two or more a click in the viewer (and the editor's View mode) opens a menu of them at the pointer, each firing `mmdx-link`. New string: `view.links`.
- **The page setting `blockTags`** (`%%@ canvas {"blockTags":false}`) hides the sequence blocks' kind tags, and the sequence page preset **Blocks without kind tags** (`plain-blocks`, in the eight built-in themes) sets it; a block's own `showTag` still wins.
- **Sequence editing that keeps the code as written**: the message toolbar's arrow popover writes Mermaid's ten arrows in two rows, solid and dotted (only the token changes; `()` and `+` / `-` stay; half arrows are kept, not offered), **Reverse** swaps a message's ends (refused for a message to its sender and where processes would no longer balance), and a message's end circle dragged sideways to another lifeline re-attaches that end; a note's toolbar and Properties place it left of, right of or over its participant, and stretching a note keeps `left of` / `right of` while it covers one participant; an `alt`, `par` or `critical` block's toolbar has **Add branch** (`else`, `and`, `option` at the end of the block) and **Delete the last branch**, and its Properties the branch conditions as rows with Add branch and a Delete per branch; the Shapes menu adds Parallel, Critical region and Break; a participant rename changes only its alias (`as …`, or `@{ "alias" }` when that is the form in use) and keeps `create`, the id and `@{…}`. New strings: `seq.arrow`, `seq.reverse`, `seq.reattached`, `seq.reattach`, `seq.noteLeft`, `seq.noteRight`, `seq.noteOver`, `seq.placement`, `seq.place.left of`, `seq.place.right of`, `seq.place.over`, `seq.addBranch`, `seq.addBranchTip`, `seq.deleteBranch`, `seq.deleteBranchTip`, `seq.deleteLastBranch`, `seq.branches`, `seq.branchesHint`, `tb.codeArrow`, `tb.codeArrowSolid`, `tb.codeArrowDotted`.
- **ER syntax as Mermaid's lexer reads it** (one grammar in 11.17 and 12.2, reproduced rule by rule, the model checked against Mermaid's ErDB): ids, attribute types and names with any non-ASCII character (Unicode and emoji) and quoted names; every cardinality spelling (21, plus `u`, drawn as exactly one with the info `er.md-parent`) and the non-identifying lines `.-` and `-.`; `type?` optional attributes (11.16+); `classDef` (merged), `classDef default`, `class`, `:::a,b` (also on relationship ends) and `style` on tables and subgraphs, a class naming a preset drawing that preset; the frontmatter (its `title` drawn above the diagram), `accTitle` / `accDescr` (and the block form) as the SVG's `<title>` / `<desc>`; aliases drawn as markdown (bold and italic); a relationship to itself drawn as a loop with both cardinality markers, its label and its line, with room for it in the layout. Errors where Mermaid fails: `er.header`, `er.rel-label` (a relationship without its label, drawn, with the fix **Add an empty label**), `er.rel-alias` (an alias on a relationship line, read, with a fix that gives it its own line), `er.unclosed`; warnings: `er.title-statement` (drawn as the title, with a fix that moves it to the frontmatter), `er.subgraph-later`, `er.id-clash`, `er.bad-style`. An [ER diagrams](https://udamir.github.io/mmdx/guide/er) guide page describes them.
- **ER subgraphs** (Mermaid 11.17+): `subgraph id [Title]` … `end`, nested, with `direction`, classes and styles, and Mermaid's membership rule (the first subgraph to close that names a table holds it); drawn as frames in the flowchart's subgraph style and group presets, laid out with the compound layout (each subgraph in its own direction, Mermaid's rule for it, hand-placed tables and frames kept, relationships routed around frames and tables that hold neither end); a relationship to a subgraph ends on its frame. In the editor: ⌘G wraps tables and subgraphs of one scope in a subgraph, Ungroup and Delete remove the frame and keep its contents, a table dropped on a subgraph is written into it, Properties set a subgraph's Direction, and its title is edited in place. The diff matches subgraphs by id; a move into another subgraph is a layout change. New string: `er.dirDefault`.
- **Lossless ER editing**: a relationship edit rewrites only the cardinality, line, label or end that changes, in the form written there (words stay words, symbols stay symbols); an alias is rewritten where Mermaid reads it, with `:::` classes and blocks kept; ids, labels and titles are quoted where Mermaid would not read them as one word; a table that lived only in a deleted or reconnected relationship stays declared; a copy of a table in a subgraph goes into the same subgraph.
- An example: ERD: Online shop by domain (subgraphs, classes, a markdown alias, a relationship to itself, the frontmatter title).
- **Animated connectors in the editor**: **Animation** (Off, Fast, Slow) in a flowchart connector's line popover and in Properties writes Mermaid's edge data (`animate: true`, `animation: slow`), giving the edge an id (`A e1@--> B`) when it has none.
- **Rich text labels in the editor**: the floating toolbar's B opens a text format menu — bold, italic, underline, strikethrough (`⌘B`, `⌘I`, `⌘U`, `⇧⌘X` in the text box) — that formats the selected words, or the whole text when none is selected; while some words are selected, the font, size, alignment, link and text colour (which Mermaid applies only to a whole label) are off. Flowchart and mindmap labels draw `<u>…</u>` and `<s>…</s>` (also `<del>`, `<strike>`) in markdown strings, as stock Mermaid passes them through.
- **`wheel: 'zoom'`**: the mouse wheel zooms at the pointer, and Shift + wheel and a sideways scroll pan — a new value of the viewer's and `<mmdx-diff>`'s `wheel`, and a new `wheel` option and attribute of `<mmdx-editor>` and `<mmdx-studio>` (default `always`).

### Changed (breaking)

- **`SequenceModel` has `numbering`** (every `autonumber` statement) and `accTitle` / `accDescr`, a `SeqMessage` its `arrow` as written (and `half`, `stick`, `reverse`, `central`), a `Participant` `createdBy`, `destroyedBy`, `links` and `properties`; **`ErModel` has `groups`** (`ErGroup`), `classDefs`, `undefinedClasses`, `headerLine`, `title`, `accTitle` and `accDescr`, an `Entity` `alias`, `classes`, `style`, `parent` and `stmts`, an `ErRel` the offsets of its tokens, and `ErGeometry` `groups`. An ER relationship's `from` or `to` may be a subgraph's id. Code that builds these models by hand needs the new fields.
- **`<mmdx-studio>` keeps no diagram in the URL**: no `#d=…` in the address bar and no Share button; `persist` takes only `local`.
- **`encodeHash` and `decodeHash` are removed** from `@mmdx/studio` and `@mmdx/studio/adapters`.
- **`Kinds` is the diagram types' view kinds by type** (`ALL_KINDS.flowchart`, …) instead of `{ parsers, renderers }`; the `…With` functions take it as before.
- **`CoreContext` has `icons`**, an icon registry (and the render context an icon lookup): `createContext()` and the components fill it; a context built by hand needs it (`createIconRegistry()`).
- **`rehypeMmdx`'s transformer returns a promise** when the page's diagrams reference icons that are not loaded yet (unified awaits it); without such icons it stays synchronous.
- **`CoreContext` has an `imagePolicy`** (and so does the render context): `createContext()` and the components fill it with `DEFAULT_IMAGE_POLICY`; a context built by hand needs it.
- **`NodeShape` is a shape catalogue id** (`ShapeId`): the 17 former names plus Mermaid's short names for the others; `queue`, which no parser produced, is gone (the name reads as the horizontal cylinder). `FlowchartModel` has `statements` (the code offsets the editing ops splice), and a node its `@{…}` data (`data`, `blocks`).
- **`DiagramType`, `DiagramModel`, `SupportedModel` and `GeometryIndex` include mindmaps** (`'mindmap'`, `MindmapModel`, `MindmapGeometry`), `ResolvedTheme` has a `mindmap` section and `Summary.key` can be `label.mindmap`: code that switches over every diagram type needs a mindmap case.
- **`DiagramType`, `DiagramModel`, `SupportedModel` and `GeometryIndex` include state diagrams** (`'state'`, `StateModel`, `StateGeometry`), `ResolvedTheme` has a `state` section, `PageSettings` has `composites` and `Summary.key` can be `label.state`: code that switches over every diagram type needs a state case.
- **A flowchart edge's `id` is its own id when the code gives it one** (`A e1@--> B` is `e1`; `key` keeps `A->B`), and `EdgeLine` has `invisible` (`~~~`). A node with `icon` or `img` data has the shape `icon` or `image`, as Mermaid draws it.

### Changed

- **Fit fills the canvas**: in the editor and the viewer, Fit (and the first view of a diagram) zooms the page to the whole canvas, under the floating panels and the tool dock, instead of the free strip between them; the editor keeps a 16 px margin (40 before) and room above the page for its badge. The diff keeps its panes clear of the panels.
- **Sequence diagrams look as Mermaid draws them**: dotted messages (`-->>`, `-->`, `--x`, `--)`) are dashed — the built-in themes' `message.replyDash` is `"4 3"` (a preset's or the message's own `dash` still wins) — and blocks show their kind (`loop`, `alt`…) in a tag at the corner (`block.showTag` is `true`); created participants are drawn at their creating message's row and destroyed lifelines end with a cross. Every existing sequence diagram changes look; the **Blocks without kind tags** page preset hides the tags again.
- **ER diagrams are read as Mermaid reads them**, which changes what some files mean: a relationship label is one word or a quoted text (`: places order` labels "places" and adds a table `order`), a table's alias is the first one written, `direction TD` is two tables (`direction` and `TD`), and cardinality words and keywords (`one`, `many`, `to`, `end`, `class`…) cannot be bare ids. `er.cannot-parse` and `er.bad-attribute` are errors now (Mermaid fails on those lines); the line is still skipped and the rest drawn. `---` frontmatter is no longer read as a table.
- **The edit kind gained `actions`** (one-click buttons of an item's toolbar: Reverse, the note placements, Add / Delete branch) and **`codeArrow`** (arrows written in the code, offered by the arrow popover with previews); the toolbar has an `actions` control. An ops kind's `descendants` may name the item kind of its leaves (`leaf`), so the group code moves ER tables.
- **The stock Mermaid fallback sets theme, look and layout**: the viewer's fallback and the editor's Plain Mermaid preview give Mermaid its theme (`default` / `dark`), the `classic` look and the `dagre` layout explicitly, since Mermaid 12 changed those defaults (`redux-color`, `neo`, ELK); renders look the same with Mermaid 10, 11 and 12.
- **Mermaid 12.2 is the development dependency** (the fallback, the stories, the docs), with 11.17.2 installed as `mermaid-11`: the parsers and every editing op of every diagram type are checked against both versions. The peer range stays `mermaid >= 10`.
- The diff compares a sequence message's arrow as written (`->>` against `-->>`, a half arrow, `()`), and an ER table's classes and Mermaid styles as style changes.
- `seq.unsupported` is gone (`accTitle`, `accDescr` and `destroy` are read), and the string `group.noEr` with it: ER diagrams have groups.
- **Automatic layout of flowcharts with subgraphs**: each subgraph is laid out as a container of its own and moves as one box, so subgraph frames no longer overlap each other or other nodes, nested subgraphs sit inside their parents with room for their titles, connectors go around subgraphs that hold neither of their ends, and a link to a subgraph ends on its frame (it went to the subgraph's first node). Plain Mermaid files with subgraphs, and nodes added later to diagrams laid out by hand, are placed differently than before; diagrams whose nodes all have stored positions look the same. In a diagram with some hand-placed items, new items go below the hand-placed ones of their own subgraph rather than below the whole diagram. `%%@ canvas {"layout":"legacy"}` keeps the earlier layout for one minor release.
- **The editor loads diagram types on demand**: the code of a type arrives the first time a document of that type is shown (the editor's first chunk is about 15 kB smaller); `whenLoaded()` also waits for it.
- **Each diagram type plugs in through one set of kinds** (view, diff, ops and edit), so adding a type no longer means edits all over the code base ([Contributing → Adding a diagram type](https://udamir.github.io/mmdx/guide/contributing#adding-a-diagram-type)). The edit kind gained `imageInMeta` (a type without image syntax keeps pictures in metadata) and `pageOptions` (page settings a type writes its own way, as Page properties selects), and item previews can differ per diagram type (`previewKind`).
- **The edit kind gained `properties`** (controls of a type's own in an item's Properties: a state's kind and description rows, a composite's direction and Add region, a note's side) and **`ungroupConfirm`** (a question before Ungroup), and a connection a type refuses shows its reason as a toast.
- **The shapes start, end, choice, fork / join and note** moved to a module of their own that the state diagram's code registers, so the viewer of a state diagram needs no other shape chunk; they stay in the catalogue for flowcharts.
- **A drag no longer counts towards a double-click** in the editor: a quick press and drag (or two quick drags) does not open the text editor or enter a group, and an item ends where it was let go even when the pointer's last move came late.
- **Deleting in the editor carries positional metadata over**: the metadata of items numbered by their place in the code (mindmap nodes without an id) follows them when a deletion renumbers them.
- **The editor writes shapes to the Mermaid code**: the shape picker, Properties and the Shapes menu write a bracket (`A{"…"}`) or, for shapes without one, a separate `A@{ shape: lin-cyl }` statement after the graph's statements (Mermaid Chart's style), so the file shows the same shapes in stock Mermaid. Metadata `shape` is left for shapes Mermaid lacks and for nodes whose preset draws another shape. Shapes older files keep in metadata move to the code when the node is edited or through the `flow.meta-shape` fix, never on a plain save.
- **Connectors end on a shape's outline** (the slopes of a diamond or hexagon, a circle, a document's wave) instead of its box; the editor's ports and magnets and the diff's highlight frames follow the outline too.
- **Relabelling, reconnecting and deleting keep the code as written**: node data, edge lengths and styles, chains, `&` groups, `:::` classes and edge ids stay; a statement is split only where an edit breaks it apart.
- **One list of shapes**: the shape picker (now every flowchart shape, by category), Properties, the theme editor's shape tabs and the Shapes menu read the catalogue; a theme's `nodeShapes` may name a shape by any of its names (`cyl`, `lean-r`).
- **`@{ shape: f-circ }`, `sm-circ`, `fr-circ` and `lin-cyl` look like Mermaid's**: they were drawn as a plain circle or cylinder.
- **Emoji are measured as one glyph on the server**: the static measurer (SSR, `renderToSvg`, the markdown plugins) counts graphemes, so `👨‍👩‍👧`, `❤️`, `👍🏽` and flags are 1.15 em wide instead of one em per code point, and boxes with emoji no longer come out too wide. Text without emoji measures as before.
- **The shapes beyond the 17 former ones load on demand** in the viewer, History and `<mmdx-diff>`: their drawing code (about 4 kB gzip) arrives the first time a diagram shows one of them, and a page of flowcharts with the common shapes does without it; the editor loads it with its flowchart code. SSR, `renderToSvg`, the markdown plugins and the render worker draw every shape as before.
- **Flowchart links have Mermaid's length**: `---`, `===`, `-.-`, `-.->` and labelled links (`-- a -->`) were one rank too long, so automatic layouts of diagrams with them change (the dashes, equals or dots beyond the shortest form count, as in Mermaid).
- **Markdown strings are no longer reported** as shown as plain text (`flow.markdown-label` is gone), nor edge ids and edge data as unsupported (`flow.edge-id`).
- **The code that draws rich labels, icons and images loads on demand** in the viewer, History and `<mmdx-diff>`, with the shapes beyond the 17, the first time a diagram needs it; the editor, SSR, `renderToSvg`, the markdown plugins and the render worker have it at once.
- **An icon is an image node's source in a flowchart**: the dock's Image adds an image node, and the floating toolbar's **Change image** picks a picture or an icon for it (an image node given an icon becomes an icon node, and back); its **settings** next to it hold, per source, the icon's frame or the picture's fit, and the label position. Sizes and **Keep aspect ratio** moved from the toolbar (its H field, the popover's width and lock) to Properties, and a new picture keeps its aspect ratio (`constraint: "on"` is written with it). Other flowchart shapes lose the toolbar's Icon button and Properties' icon picker (a label's existing icon token is still drawn and can be converted to an icon node); mindmap nodes and sequence participants keep their Icon button; ER diagrams have no icons (a token in an alias is its text).
- **Images in state diagrams work as in flowcharts**: an image state is the flowchart's image node, kept in metadata (Mermaid has no syntax for it) — the picture is the state, its title and description rows the caption, with the flowchart's keys: `img` or `icon` (the toolbar's **Change image**: a picture or an icon), `w` / `h`, `constraint`, `pos`, `form` and `imgFit`, the same settings in the toolbar and Properties, the same resize handle and the same connector ends. The dock's Image adds one at 200 × 200, caption below, the aspect kept. A picture no longer sits above the title in a state box, and a plain state has no Icon button (a title's icon token is still drawn); `imgW` / `imgH` still size a picture where `w` / `h` are not written. The portable export counts an icon state's icon as mmdx-only, as a picture.
- **No "Make rich text"**: a flowchart or mindmap label is rich text whenever it is edited, and is written as a markdown string once it has formatting; the small B / I bar above the text box is gone (its buttons are in the toolbar's text format menu). For those labels the toolbar's Bold formats the text instead of switching the style's font weight.
- **Zoom, pan and editing stay responsive on large diagrams**: a wheel or pinch zoom and a wheel or drag pan are shown as a CSS transform of the canvas and written to the drawing once the gesture rests (300 ms after a zoom, 150 ms after a pan, or on the way once a pan has moved a quarter of the canvas), so the text is laid out once per burst instead of on every step; the patcher leaves items that did not change alone; `--dx-inv` is set only while diff badges may be shown; colours are resolved once per theme and diagram palette; the multi-selection is marked in one pass; toolbars are not placed while an item is dragged; keyboard tab stops are updated when the page is idle.
- **The editor's page has a 1 px edge instead of a blurred shadow**: the blur redrew the whole screen on every repaint once zoomed in.
- A `title` statement in a flowchart is drawn but reported (`flow.title-statement`: stock Mermaid fails on it), with a fix that moves it to the frontmatter.

### Fixed

- `configure({ mermaid })` after a fallback render is the Mermaid the next render uses; the first instance used to stay.
- The ER editor writes ids Mermaid cannot read bare (with spaces, keywords, cardinality words) in quotes instead of breaking the code, and relationship edits no longer rewrite word cardinalities as symbols or lose an alias written on a relationship line.
- A sequence participant rename keeps its `@{…}` data and `create`, and relabelling a `rect` no longer overwrites its colour; `autonumber off` stops the numbers and `autonumber 10 5` starts at 10 in steps of 5 (both used to turn numbering on from 1); `A->>()B` no longer creates a participant `()B`.
- An unknown `@{ shape }` name is reported instead of silently becoming a rectangle; `notch-rect` and the other hyphenated names Mermaid documents are read.
- A `}` or `,` inside a quoted `@{ label: "…" }` no longer ends the node data; single-quoted labels are read.
- Diagrams rendered in the render worker (over 300 lines) use the component's link policy instead of the default one.
- A flowchart's `accDescr { … }` block no longer turns its lines into nodes, and the target of a `~~~` link is no longer lost.
- `classDef default` and classes on subgraphs are applied; `stroke-dasharray: none` clears a dash.
- `</br>` breaks a line in labels, as `<br>` does.
- Giving a label to a node defined only by its node data no longer writes it into the frontmatter.

## 0.2.0 — History and diff

The editor and the viewer get a History of the diagram, `<mmdx-diff>` compares any two versions, and a DOM-free diff API serves CI bots. Every component shares the editor's chrome.

### Added

- **`<mmdx-diff>` and `DiagramDiff`**: Before, Merged, After and Side by side views of two versions, with change filters, Code, history, change list and Layers panels, review tools and exports (PNG, SVG, `.mmdx`, patch, Markdown or JSON report).
- **History in the editor and the viewer**: a `history` property adds a History button to view, compare and (in the editor) restore older versions; `mmdx-history-*` events and `historySession`.
- **History adapters**: `staticHistory(versions)` and `httpHistoryAdapter(url)`.
- **Core diff API** (`@mmdx/studio/core`): `diffDiagrams`, `renderDiffToSvg`, `diffReport`, `unifiedDiff` and more.
- **Studio**: document versions (Save version, ⌘S), Diff mode, example previews and example histories.
- **The theme menu everywhere**, the editor's chrome in the viewer, and `compact` and `features` attributes.
- The clipboard carries content between documents; elements keep their state when moved in the DOM.
- React wrapper `MmdxDiff`.

### Changed

- The editor's ⋯ menu is gone; hosts use the `openFiles` and `autoLayout` actions.

### Changed (breaking)

- **`canvas.theme` left the `.mmdx` format**: the theme comes from the component (`theme` / `theme-dark`, the user's pick, or the default pair).
- Theme and light / dark are independent.
- `EditorModule` is `ViewModule<EditorCore>` (`install(scope)`).
- Remembered preferences use per-component keys.
- `element.instance` is `null` while the element is not connected.
- An attribute applies one option; removing it restores the default.

### Upgrading from 0.1

- Set the theme on the element or through the `theme` option of `renderToSvg` and the markdown plugins.
- Rewrite custom editor modules as `{ id, install(scope) { const core = scope.core; … } }`.
- Check for `element.instance === null` instead of `undefined`.
